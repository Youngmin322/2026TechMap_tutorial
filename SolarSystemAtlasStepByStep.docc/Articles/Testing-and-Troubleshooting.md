# 테스트와 문제 해결

모델 로딩, 공간 배치, 입력, 접근성, 문서 링크를 순서대로 검증합니다.

## Overview

### 실행 전 체크리스트

- `RealityKitContent.rkassets`에 `Sun.usdz`와 여덟 행성 USDZ가 있고, `Planet.starter`의 모든 `assetName`이 파일 이름과 대소문자까지 일치하는지 확인합니다.
- `orbitDuration`과 `rotationDuration`이 모두 0보다 큰지 확인합니다.
- 볼륨 기본 크기 안에서 가장 바깥 궤도와 정보 카드가 잘리지 않는지 확인합니다.
- 태양과 행성이 로드되기 전에도 빈 화면 대신 진행 상태나 오류 표시가 보이는지 확인합니다.

### 증상별 확인 지점

#### 특정 행성이 보이지 않음

먼저 `assetName`과 USDZ 이름의 대소문자를 비교합니다. 이름이 맞다면 `visualBounds`의 크기가 0인지, `fittedModel`이 계산한 배율이 지나치게 크거나 작은지 확인합니다.

#### 행성을 탭할 수 없음

`InputTargetComponent`만으로는 충분하지 않습니다. 탭할 표면을 설명하는 `CollisionComponent`가 같은 엔티티 또는 적절한 자식에 있어야 합니다. 제스처가 `targetedToAnyEntity()`로 설정되었는지도 확인합니다.

#### 레이블이 행성과 어긋남

행성과 attachment가 같은 `orbitAngle`, `radius`, `diameter`로 위치를 계산하는지 확인합니다. update 클로저에서 모델과 레이블을 모두 갱신해야 합니다.

#### 애니메이션이 튀거나 다시 시작함

시작 시각이 body 평가 때마다 새로 만들어지지 않도록 `@State`에 보관합니다. 매 프레임 각도를 누적하는 대신 경과 시간에서 진행률을 계산합니다.

### 상호작용과 접근성

- 선택한 행성은 크기 변화뿐 아니라 정보 카드의 이름으로도 식별할 수 있어야 합니다.
- 닫기 버튼에는 `도감 닫기`처럼 동작을 설명하는 접근성 레이블을 제공합니다.
- 모델 로딩 중인 `ProgressView`에는 어떤 행성을 기다리는지 알 수 있는 레이블을 제공합니다.
- 머리 움직임이나 시야 변화에도 레이블과 카드가 다른 행성을 과도하게 가리지 않는지 기기에서 확인합니다.

### DocC 품질 확인

문서 빌드는 누락된 이미지, 잘못된 `<doc:...>` 링크, 유효하지 않은 튜토리얼 지시문을 경고로 보고합니다. 프로젝트의 `build-docs.sh`는 경고를 오류로 취급하므로, 성공 메시지가 나오면 문서 카탈로그의 내부 링크와 리소스 참조가 모두 해석된 상태입니다.

생성된 `docs/`는 결과물입니다. 문구나 이미지를 수정할 때는 `Sources/SolarSystemAtlas/SolarSystemAtlas.docc`를 바꾸고 다시 빌드하세요.
